# 🎧 HowTune 仕様書（iOS ネイティブ）

> **Spec-Driven Development / Phase: Specify**
> 本書は「何を / なぜ」を定義する。実装手段（音源・DB・推論位置等）は plan.md で決定する。
> **本書は git を source of truth とし、Notion はそのミラー（閲覧用）である。編集は必ず git 側で行う。**

---

## 1. Constitution（プロジェクト原則・固定）

本仕様および以降のすべての設計判断は、以下の原則に従う。

- **P1. How でつなぐのであって What ではない。** 「同じ曲」ではなく「同じ聴き方」を中心に据える。曲・アーティスト・ジャンル中心の UI に退行しない。
- **P2. AI は断定しない、対話の起点を作る。** センサーや AI は「あなたはこれが好き」と決めつけず、「ここで反応していた、どうだった？」と問う。最終的な言語化はユーザーが行う。
- **P3. 自動確定しない。** AI 生成テキスト（質問・How カード）は必ずユーザーの確認・編集を経て確定する。自動投稿しない。
- **P4. センサーは前提にしない。** AirPods 未接続・モーション/ヘルス権限が無い場合でも、最低限の体験（手動ラベル）が成立する。
- **P5. プライバシー優先。** モーションデータは最小限取得・端末内処理優先とし、秘密情報（API キー等）を git に含めない。
- **P6. 実装手段は仕様に持ち込まない。** 「音楽が再生でき、再生位置が取得できる」は要求。音源が何かは設計判断（plan.md）。

### 対象プラットフォーム（固定事項）

本プロダクトは **iOS ネイティブアプリ（Xcode / SwiftUI）** を対象とする。Web 版は作らない。
身体反応の主シグナルは **AirPods の頭部モーション**である。
これは Web の `DeviceMotionEvent` では取得できず、`CMHeadphoneMotionManager` などネイティブ API を必須とするため、ネイティブを固定事項とする。

## 2. Overview / Purpose

**AirPods の頭部モーション**で「曲中のどこで身体が反応したか」を検出し、歌詞行や曲中区間に対するコメントを通じてユーザーの**音楽の楽しみ方（How）**を言語化・可視化し、**同じ曲の一部分の聴き方で人とつなげる iOS ネイティブアプリ**を構築する。

---

## 3. Scope

### 3.1 In Scope（MVP）

- AirPods 接続・頭部モーション取得可否の確認・オンボーディング
- 楽曲の再生と再生位置（曲中時刻）の取得
- **AirPods 頭部モーション**の取得と曲中時刻への同期記録
- 反応区間の検出と 3 状態聴取スコア（groove / chill / neutral）の取得・表示
- **反応地点に対応する歌詞行の表示（歌詞 API 連携）**
- 反応地点に基づく AI 対話
- 対話結果からの How カード生成・編集・保存
- 同じ How を持つ人 / 曲 / リスナーの表示

### 3.2 Out of Scope（MVP では作らない）

- 本格的な音源解析、高精度 BPM 推定
- 教師データ収集アプリ（**別仕様 `002-` として切り出す**。MVP 本体には含めない）

---

## 4. Personas

- **P-LISTENER（一般リスナー）**: 音楽は好きだが「どこが好きか」を言語化できない人。AirPods 等モーション対応イヤホンの利用者。主たる利用者。
- **P-EXPLORER（考察好き）**: 自分の聴き方を発信し、近い価値観の人とつながりたい人。

## 5. User Stories

| ID | ストーリー |
|---|---|
| US-01 | リスナーとして、初回に AirPods 頭部モーションが使えるか確認したい。反応の解釈精度を上げるため。 |
| US-02 | リスナーとして、曲を再生し、聴きながら頭の動きが自動で記録されてほしい。意識せず自然に聴くため。 |
| US-03 | リスナーとして、曲のどのあたりで自分が反応したかを後から見たい。自分の聴き方を振り返るため。 |
| US-04 | リスナーとして、反応した地点について AI に問いかけられ、対話しながら「どう好きか」を言葉にしたい。 |
| US-05 | リスナーとして、対話結果が How カードになり、自分で編集・確定したい。発信できる形にするため。 |
| US-06 | エクスプローラーとして、自分と同じ How を持つ人・曲・リスナーを見たい。近い価値観とつながるため。 |
| US-07 | AirPods 非接続・センサー非対応の状況でも、手動で状態を選んで体験が成立してほしい。 |
| US-09 | リスナーとして、反応地点の歌詞を見ながら「どの言葉に刺さったか」を語りたい。 |

## 6. Functional Requirements（EARS 記法）

> 記法: Ubiquitous「〜shall」/ Event「When …, shall」/ State「While …, shall」/ Optional「Where …, shall」/ Unwanted「If …, then shall」

### 6.1 ONB — オンボーディング / 権限

- **FR-ONB-01** *When* ユーザーが利用開始操作を行った時, システムはユーザー操作起点でモーション利用許可を要求 *shall*。
- **FR-ONB-02** *When* AirPods 頭部モーションが利用できない時, システムは手動モードへの導線を提示 *shall*。
- **FR-ONB-03** *If* AirPods が未接続、権限が拒否、または端末/イヤホンが非対応の場合, *then* システムは手動ラベルモードへの導線を提示 *shall*。
- **FR-ONB-04** システムはモーションデータ取得の目的を提示 *shall*。

### 6.2 PLAY — 再生 / 再生位置（音源非依存）

- **FR-PLAY-01** システムは 1 曲を再生・一時停止できる手段を提供 *shall*。
- **FR-PLAY-02** *While* 再生中, システムは現在の曲中時刻（再生位置）を継続的に取得・表示 *shall*。
- **FR-PLAY-03** システムは再生位置をセンサー記録および反応検出の基準時刻として供給 *shall*。
- **FR-PLAY-04** *If* 再生位置の取得手段が利用できない場合, *then* システムはユーザーにその旨を通知し、当該セッションの反応同期を無効化 *shall*。
  > 注: MVP の音源・再生位置取得は MusicKit を使う（DECISION-01）。

### 6.3 SENS — モーション取得状態

- **FR-SENS-01** *While* リスニング中かつ AirPods 頭部モーションが利用可能な時, システムは AirPods の加速度・回転速度・姿勢を曲中時刻に同期取得 *shall*。
- **FR-SENS-02** システムは取得状態（取得中 / 停止 / 未接続 / 非対応）を可視化 *shall*。
- **FR-SENS-03** *While* センサー取得中, システムは UI の操作応答性を維持 *shall*（取得処理が UI を阻害しない）。

### 6.4 HMOTION — 頭部モーション取得（AirPods）

- **FR-HMOTION-01** *While* AirPods 接続かつ許可済み, システムは頭部の加速度・回転速度・姿勢を `CMHeadphoneMotionManager` で曲中時刻に同期取得 *shall*。
- **FR-HMOTION-02** システムは頭部モーションの取得状態（接続中 / 未接続 / 非対応機種）を可視化 *shall*。
- **FR-HMOTION-03** *If* セッション中に AirPods が切断された場合, *then* システムは取得停止を表示し、手動モードで体験継続できる導線を持つ *shall*。

### 6.5 HR — 心拍取得

HealthKit / 心拍連携は現行実装から削除済みであり、MVP の要件には含めない。

### 6.6 DETECT — 反応検出 / スコアリング

- **FR-DETECT-01** システムは 2 秒の時間窓ごとに頭部モーション特徴量（meanMagnitude / stdMagnitude / maxDelta / energy / peakCount / rhythmRegularity / stillness）を抽出 *shall*。
- **FR-DETECT-02** システムは 3 状態スコア（groove / chill / neutral）を取得 *shall*。
- **FR-DETECT-03** *While* リスニング中, システムは反応の出方をリアルタイムに表示 *shall*。
- **FR-DETECT-04** システムは検出された反応区間を曲中タイムライン上に提示 *shall*。
  > 注: 推論を端末上（Core ML）で行うか、特徴量を送信して外部で行うかは plan.md の決定事項。端末上（Core ML）が有力（DECISION-02）。

### 6.7 LYRIC — 歌詞表示

- **FR-LYRIC-01** *Where* 対象曲の時間同期歌詞が取得できる場合, システムは反応地点に対応する歌詞行を表示 *shall*。
- **FR-LYRIC-02** *If* 歌詞が取得できない場合, *then* システムは歌詞なしで反応地点（時刻）のみを提示 *shall*。
  > 注: 歌詞ソース（API / 同期方式）は plan.md の決定事項（DECISION-08）。

### 6.8 DLG — AI 対話

HowChat 画面と mock/legacy client は残すが、現行 Functions 本番 API には `/sessions` 系 AI endpoint を実装していない。

- **FR-DLG-01** *When* mock mode が有効な時, システムはその地点に基づく確認形の問いかけを提示 *shall*（断定形は不可、P2 準拠）。
- **FR-DLG-02** システムは選択肢回答と自由入力の双方を受け付け *shall*。
- **FR-DLG-03** *If* AI endpoint が利用できない場合, *then* システムは mock 応答または手動入力へフォールバック *shall*。

### 6.9 CARD — How カード

- **FR-CARD-01** システムは曲中区間に紐づく How コメントを作成 *shall*。
- **FR-CARD-02** システムはコメント、開始秒、終了秒、曲 ID、アーティスト ID を保存 *shall*。
- **FR-CARD-03** *When* ユーザーが確定操作を行った時にのみ, システムはカードを保存 *shall*（自動確定不可、P3 準拠）。
- **FR-CARD-04** システムは保存済みコメントの一覧・詳細・いいねを表示 *shall*。

### 6.10 COMM — コミュニティ（同じ How でつながる）

- **FR-COMM-01** システムはユーザー自身の How を表示 *shall*。
- **FR-COMM-02** システムは同じ How を持つ人 / 同じ How で聴かれている曲 / 近い聴き方のリスナーを表示 *shall*。
- **FR-COMM-03** システムは How タグでの絞り込みと人気 How タグの表示を提供 *shall*。
- **FR-COMM-04** *Where* 共有機能が含まれる場合, システムは How カードの外部共有導線を提供 *shall*。

### 6.11 MANUAL — 手動ラベル（センサー代替）

- **FR-MANUAL-01** *While* 手動ラベルモードかつ再生中, システムは状態ボタン（groove（ノってる） / chill（チルい） / neutral）を提供 *shall*。
- **FR-MANUAL-02** *When* 状態ボタンが押された時, システムは押下時刻を反応地点として記録 *shall*。

## 7. Non-Functional Requirements

| ID | カテゴリ | 要求 |
|---|---|---|
| NFR-01 | 互換性 | **iOS 専用**。対応 iOS バージョン、および頭部モーションに対応する AirPods 機種を明記する。 |
| NFR-02 | 互換性 | AirPods のサンプリングレート差を前提に、特徴量計算はレート非依存とする。 |
| NFR-03 | 性能 | センサー取得・特徴量抽出はメインスレッドを阻害しない。リアルタイム表示は再描画を最小化する。 |
| NFR-04 | 性能 | 連続センサー取得＋再生時の電力・発熱を抑制する。不要時は取得を停止する。 |
| NFR-05 | リアルタイム | 反応検出から問いかけ提示までの遅延を体感的に短く保つ。 |
| NFR-06 | プライバシー | モーションは最小限取得。取得目的の事前提示と端末内処理を優先する。 |
| NFR-07 | セキュリティ | API キーを git やクライアントバイナリに含めない。認証トークンは iOS Keychain に安全に保持する。自由入力をサニタイズ。 |
| NFR-08 | 信頼性 | 通信断でセンサーデータを失わない（ローカルバッファ→再送）。カード生成・回答送信はリトライ可能。 |
| NFR-09 | アクセシビリティ | VoiceOver・Dynamic Type 対応（特に再生・ラベルボタン）。 |
| NFR-10 | 国際化 | 文言を外部化し将来の多言語化を阻害しない。 |
| NFR-11 | 計測 | How カード作成数・共有率・同じ How 経由の接続数・継続率をイベントとして発火する。 |
| NFR-12 | ヘルスデータ | HealthKit / 心拍連携は現行 MVP から削除済み。ヘルスデータを取得しない。 |

## 8. Acceptance Criteria（受け入れ条件・抜粋）

- **AC-01 (US-01)**: 初回フローで AirPods 頭部モーションの利用可否を確認できる。利用できなくても手動ラベルモードに進める。
- **AC-02 (US-02)**: 再生中、頭部モーションが曲中時刻に同期して記録され、取得状態が画面で確認できる。
- **AC-03 (US-03)**: 再生終了後、反応区間がタイムライン上に時刻付きで表示される。
- **AC-04 (US-04)**: 反応地点ごとに確認形（断定でない）の問いかけが出て、選択肢／自由入力で回答でき、深掘りできる。
- **AC-05 (US-05)**: 対話から How カードが生成され、編集後に確定操作をするまで保存されない。
- **AC-06 (US-06)**: 自分の How に対し、同じ How の人・曲・リスナーが一覧表示され、How タグで絞り込める。
- **AC-07 (US-07)**: AirPods 非接続・非対応でも、手動ラベルで How カード生成まで到達できる。
- **AC-08 (NFR)**: センサー取得中もスクロール・タップ操作が滑らかに反応する。
- **AC-09 (US-02)**: AirPods 接続時は頭部モーションが記録され、未接続時は手動モードへフォールバックできる。
- **AC-10**: HealthKit / 心拍権限を要求しない。
- **AC-11 (US-09)**: 時間同期歌詞が取得できる曲では、反応地点に対応する歌詞行が表示される。

## 9. Decisions（確定 / 未決）

### 9.1 確定（grill 2026-05-24）

> 設計審問（grill）で確定した決定。

- **[DEC-A] 主シグナルは頭部モーション。** AirPods 頭部モーション（CMHeadphoneMotionManager）を主シグナルとする。
- **[DEC-B] HealthKit / 心拍連携は削除。** MVP は頭部モーションのみで成立させ、ヘルス権限を要求しない。
- **[DEC-C] 推論はルールベース主体 + Core ML 並行。** MVP は特徴量スコアと Core ML 候補で 3 状態スコアを算出する。→ DECISION-02 を解決。
- **[DEC-D] MVP はコア体験を完結。** 「聴く → 頭部モーション → 3 状態スコア → 歌詞/区間コメント → Howカードコメント保存」を確実に動かす。

### 9.2 未決（Deferred）

> SDD では未決事項を仕様段階で明示し、設計段階で解消する。

- **[DECISION-01] 音源と再生位置の取得手段。** ✅ **MusicKit で進める。** Spotify / AVFoundation は MVP では使用しない。
- **[DECISION-02] 3 状態推論の実行位置。** ✅ **DEC-C で解決**: 端末上、ルールベース主体 + Core ML 並行。
- **[DECISION-03] データ永続化先。** Firestore（iOS SDK）/ CloudKit / Supabase / その他。
- **[DECISION-04] LLM 連携経路。** 現行 Functions には `/sessions` 系 AI API は未実装。HowChat は mock/legacy client を残す。
- **[DECISION-05] 共有機能（FR-COMM-04）を MVP に含めるか。** → DEC-D により **P1**（MVP 必須から除外）。
- **[DECISION-06] 心拍のリアルタイム同期方式。** ✅ 削除済み。MVP では扱わない。
- **[DECISION-07] AirPods 心拍の取得 API と対応機種の確定。** ✅ 削除済み。
- **[DECISION-08] 歌詞ソースと時間同期方式。** ✅ Musixmatch を利用。`track.subtitle.get` を試し、失敗時は `track.lyrics.get` の静的歌詞へ fallback する。

## 10. Glossary

- **How**: 「どう聴いているか」という聴き方の価値観。曲・ジャンル等の「What」と対比。
- **How カード**: 対話で言語化された聴き方を、共有可能な形にまとめたカード（タイトル・説明・How タグ）。
- **How タグ**: groove / chill / neutral を起点とする聴取状態の分類。
- **反応区間**: 頭部モーションから検出された、身体反応が起きていた曲中の時間帯。
- **頭部モーション**: AirPods 内蔵センサーで取得する頭部の加速度・回転速度・姿勢。`CMHeadphoneMotionManager` で取得。
- **CMHeadphoneMotionManager**: AirPods 等の頭部モーションを取得する iOS（Core Motion）の API。
- **MusicKit**: Apple Music の楽曲再生・再生位置取得を提供する iOS フレームワーク。
- **Core ML**: iOS 端末上で機械学習モデルを実行するフレームワーク。
