## 1. Constitution（プロジェクト原則・固定）

本仕様および以降のすべての設計判断は、以下の原則に従う。

- **P1. How でつなぐのであって What ではない。** 「同じ曲」ではなく「同じ聴き方」を中心に据える。曲・アーティスト・ジャンル中心の UI に退行しない。
- **P2. AI は断定しない、対話の起点を作る。** センサーや AI は「あなたはこれが好き」と決めつけず、「ここで反応していた、どうだった？」と問う。最終的な言語化はユーザーが行う。
- **P3. 自動確定しない。** AI 生成テキスト（質問・How カード）は必ずユーザーの確認・編集を経て確定する。自動投稿しない。
- **P4. センサーは前提にしない。** AirPods 未接続・モーション/ヘルス権限が無い場合でも、最低限の体験（手動ラベル）が成立する。
- **P5. プライバシー優先。** モーション・心拍データは機微情報として扱い、最小限の取得・明示同意・端末内処理優先・削除手段を持つ。秘密情報（API キー等）をフロントに置かない。
- **P6. 実装手段は仕様に持ち込まない。** 「音楽が再生でき、再生位置が取得できる」は要求。音源が何かは設計判断（plan.md）。

### 対象プラットフォーム（固定事項）

本プロダクトは **iOS ネイティブアプリ（Xcode / SwiftUI）** を対象とする。Web 版は作らない。
身体反応の主シグナルは **AirPods の頭部モーション・心拍**、および **iPhone 本体のモーション**である。
これらは Web の `DeviceMotionEvent` では取得できず、`CMHeadphoneMotionManager` / Core Motion / HealthKit などネイティブ API を必須とするため、ネイティブを固定事項とする。

## 2. Overview / Purpose

**iPhone と AirPods のセンサー（頭部モーション・本体モーション・心拍）**で「曲中のどこで身体・生理が反応したか」を検出し、AI との対話を通じてユーザーの**音楽の楽しみ方（How）**を言語化・可視化（How カード）し、**同じ How を持つ人とつなげる iOS ネイティブアプリ**を構築する。

---

## 3. Scope

### 3.1 In Scope（MVP）

- AirPods 接続・センサー権限（モーション / ヘルス）取得・オンボーディング
- 楽曲の再生と再生位置（曲中時刻）の取得
- **AirPods 頭部モーション**・**iPhone 本体モーション**の取得と曲中時刻への同期記録
- **心拍（心拍数・心拍変動）の取得**と曲中時刻への対応づけ
- 反応区間の検出と 6 軸聴取状態スコアの取得・表示
- **反応地点に対応する歌詞行の表示（歌詞 API 連携）**
- 反応地点に基づく AI 対話
- 対話結果からの How カード生成・編集・保存
- 同じ How を持つ人 / 曲 / リスナーの表示

### 3.2 Out of Scope（MVP では作らない）

- 本格的な音源解析、高精度 BPM 推定
- 教師データ収集アプリ（**別仕様 `002-` として切り出す**。MVP 本体には含めない）

---

## 4. Personas

- **P-LISTENER（一般リスナー）**: 音楽は好きだが「どこが好きか」を言語化できない人。AirPods 等モーション対応イヤホンの利用者。主たる利用者。
- **P-EXPLORER（考察好き）**: 自分の聴き方を発信し、近い価値観の人とつながりたい人。

## 5. User Stories

| ID | ストーリー |
|---|---|
| US-01 | リスナーとして、初回に AirPods を接続し、モーション・心拍・ヘルスデータの利用を許可したい。反応の解釈精度を上げるため。 |
| US-02 | リスナーとして、曲を再生し、聴きながら頭の動き・身体の動きが自動で記録されてほしい。意識せず自然に聴くため。 |

## 6. Functional Requirements（EARS 記法）

> 記法: Ubiquitous「〜shall」/ Event「When …, shall」/ State「While …, shall」/ Optional「Where …, shall」/ Unwanted「If …, then shall」

### 6.1 ONB — オンボーディング / 権限

- **FR-ONB-01** *When* ユーザーが利用開始操作を行った時, システムはユーザー操作起点でモーション利用許可を要求 *shall*。
- **FR-ONB-02** *When* ユーザーが心拍機能を有効化する時, システムは HealthKit のヘルスデータ読み取り許可を要求 *shall*。
- **FR-ONB-03** *If* AirPods が未接続、権限が拒否、または端末/イヤホンが非対応の場合, *then* システムは手動ラベルモードへの導線を提示 *shall*。
- **FR-ONB-04** システムはモーション・心拍データ取得の目的を提示し、同意を取得 *shall*。

### 6.2 PLAY — 再生 / 再生位置（音源非依存）

- **FR-PLAY-01** システムは 1 曲を再生・一時停止できる手段を提供 *shall*。
- **FR-PLAY-02** *While* 再生中, システムは現在の曲中時刻（再生位置）を継続的に取得・表示 *shall*。
- **FR-PLAY-03** システムは再生位置をセンサー記録および反応検出の基準時刻として供給 *shall*。
- **FR-PLAY-04** *If* 再生位置の取得手段が利用できない場合, *then* システムはユーザーにその旨を通知し、当該セッションの反応同期を無効化 *shall*。
  > 注: 具体的な音源（MusicKit / AVFoundation 等）は plan.md の決定事項。本仕様は「再生位置が取得可能」であることのみを要求する。MusicKit が有力候補（DECISION-01）。

### 6.3 SENS — 本体モーション取得（iPhone）

- **FR-SENS-01** *While* リスニング中かつ許可済み, システムは iPhone 本体の加速度（x/y/z・合成・変化量）を Core Motion で時系列取得 *shall*。
- **FR-SENS-02** システムは各サンプルを曲中時刻に同期させ `{t, ax, ay, az, magnitude, delta}` として記録 *shall*。
- **FR-SENS-03** システムはセンサー取得状態（取得中 / 停止 / 未許可 / 非対応）を可視化 *shall*。
- **FR-SENS-04** *While* センサー取得中, システムは UI の操作応答性を維持 *shall*（取得処理が UI を阻害しない）。

### 6.4 HMOTION — 頭部モーション取得（AirPods）

- **FR-HMOTION-01** *While* AirPods 接続かつ許可済み, システムは頭部の加速度・回転速度・姿勢を `CMHeadphoneMotionManager` で曲中時刻に同期取得 *shall*。
- **FR-HMOTION-02** システムは頭部モーションの取得状態（接続中 / 未接続 / 非対応機種）を可視化 *shall*。
- **FR-HMOTION-03** *If* セッション中に AirPods が切断された場合, *then* システムは本体モーション（SENS）へフォールバックし、その旨を記録 *shall*。

### 6.5 HR — 心拍取得

- **FR-HR-01** *While* リスニング中かつヘルス権限あり, システムは心拍数（および取得可能なら心拍変動）を取得し曲中時刻に対応づけ *shall*。
- **FR-HR-02** *If* 心拍のサンプリング粒度が粗い場合, *then* システムはトレンド（上昇 / 下降 / 安定）として扱い、秒単位の断定をしない *shall*。
- **FR-HR-03** *If* ヘルス権限が無い、または心拍対応機種でない場合, *then* システムは心拍機能を無効化し、モーションのみで体験を成立させる *shall*。

### 6.6 DETECT — 反応検出 / スコアリング

- **FR-DETECT-01** システムは 5 秒の時間窓ごとに特徴量（meanMagnitude / stdMagnitude / maxDelta / energy / peakCount / rhythmRegularity / stillness、および**心拍数・心拍変動**等）を抽出 *shall*。
- **FR-DETECT-02** システムは 3 状態スコア（groove / chill / neutral）を取得 *shall*。
- **FR-DETECT-03** *While* リスニング中, システムは反応の出方をリアルタイムに表示 *shall*。
- **FR-DETECT-04** システムは検出された反応区間を曲中タイムライン上に提示 *shall*。
  > 注: 推論を端末上（Core ML）で行うか、特徴量を送信して外部で行うかは plan.md の決定事項。端末上（Core ML）が有力（DECISION-02）。

### 6.7 LYRIC — 歌詞表示

- **FR-LYRIC-01** *Where* 対象曲の時間同期歌詞が取得できる場合, システムは反応地点に対応する歌詞行を表示 *shall*。
- **FR-LYRIC-02** *If* 歌詞が取得できない場合, *then* システムは歌詞なしで反応地点（時刻）のみを提示 *shall*。
  > 注: 歌詞ソース（API / 同期方式）は plan.md の決定事項（DECISION-08）。

### 6.8 DLG — AI 対話

- **FR-DLG-01** *When* 反応区間が確定した時, システムはその地点に基づく確認形の問いかけを提示 *shall*（断定形は不可、P2 準拠）。
- **FR-DLG-02** システムは選択肢回答と自由入力の双方を受け付け *shall*。
- **FR-DLG-03** システムは回答に基づく複数ターンの深掘りを提供 *shall*。
- **FR-DLG-04** *While* AI 応答を生成中, システムは生成中状態を表示 *shall*。
- **FR-DLG-05** *If* AI 応答生成が失敗した場合, *then* システムは手動入力へフォールバック *shall*。

### 6.9 CARD — How カード

- **FR-CARD-01** システムは対話結果から How カード（タイトル・説明・How タグ）を生成 *shall*。
- **FR-CARD-02** システムは生成カードのプレビューを提示し, ユーザーの編集を受け付け *shall*。
- **FR-CARD-03** *When* ユーザーが確定操作を行った時にのみ, システムはカードを保存 *shall*（自動確定不可、P3 準拠）。
- **FR-CARD-04** システムは保存済みカードの一覧・詳細を表示 *shall*。

### 6.10 COMM — コミュニティ（同じ How でつながる）

- **FR-COMM-01** システムはユーザー自身の How を表示 *shall*。
- **FR-COMM-02** システムは同じ How を持つ人 / 同じ How で聴かれている曲 / 近い聴き方のリスナーを表示 *shall*。
- **FR-COMM-03** システムは How タグでの絞り込みと人気 How タグの表示を提供 *shall*。
- **FR-COMM-04** *Where* 共有機能が含まれる場合, システムは How カードの外部共有導線を提供 *shall*。

### 6.11 MANUAL — 手動ラベル（センサー代替）

- **FR-MANUAL-01** *While* 手動ラベルモードかつ再生中, システムは状態ボタン（ノってる / 上がった / チル / 聴き入り / 刺さった / 余韻）を提供 *shall*。
- **FR-MANUAL-02** *When* 状態ボタンが押された時, システムは押下時刻を反応地点として記録 *shall*。

## 7. Non-Functional Requirements

| ID | カテゴリ | 要求 |
|---|---|---|
| NFR-01 | 互換性 | **iOS 専用**。対応 iOS バージョン、および頭部モーション・心拍に対応する AirPods 機種（AirPods Pro / 3rd 以降 / Max・Powerbeats Pro 2 系等）を明記する。 |
| NFR-02 | 互換性 | AirPods / 本体 / HealthKit でサンプリングレートが異なる前提で、特徴量計算はレート非依存とする。 |
| NFR-03 | 性能 | センサー取得・特徴量抽出はメインスレッドを阻害しない。リアルタイム表示は再描画を最小化する。 |
| NFR-04 | 性能 | 連続センサー取得＋再生時の電力・発熱を抑制する。不要時は取得を停止する。 |
| NFR-05 | リアルタイム | 反応検出から問いかけ提示までの遅延を体感的に短く保つ。 |
| NFR-06 | プライバシー | モーション・心拍は最小限取得。取得目的の事前提示と同意。端末内処理を優先。ユーザーによる削除手段を提供。 |
| NFR-07 | セキュリティ | LLM/推論 API キーをフロントに置かない（バックエンド経由）。認証トークンは iOS Keychain に安全に保持する。自由入力をサニタイズ。 |
| NFR-08 | 信頼性 | 通信断でセンサーデータを失わない（ローカルバッファ→再送）。カード生成・回答送信はリトライ可能。 |
| NFR-09 | アクセシビリティ | VoiceOver・Dynamic Type 対応（特に再生・ラベルボタン）。 |
| NFR-10 | 国際化 | 文言を外部化し将来の多言語化を阻害しない。 |
| NFR-11 | 計測 | How カード作成数・共有率・同じ How 経由の接続数・継続率をイベントとして発火する。 |
| NFR-12 | ヘルスデータ | 心拍は HealthKit の機微情報として扱う。最小権限・明示同意・端末内処理優先・削除手段を必須とする。 |

## 8. Acceptance Criteria（受け入れ条件・抜粋）

- **AC-01 (US-01)**: 初回フローでユーザー操作を起点にモーション/ヘルス許可ダイアログが出る。拒否しても手動ラベルモードに進める。
- **AC-02 (US-02)**: 再生中、頭部モーション・本体モーションが曲中時刻に同期して記録され、取得状態が画面で確認できる。
- **AC-03 (US-03)**: 再生終了後、反応区間がタイムライン上に時刻付きで表示される。
- **AC-04 (US-04)**: 反応地点ごとに確認形（断定でない）の問いかけが出て、選択肢／自由入力で回答でき、深掘りできる。
- **AC-05 (US-05)**: 対話から How カードが生成され、編集後に確定操作をするまで保存されない。
- **AC-06 (US-06)**: 自分の How に対し、同じ How の人・曲・リスナーが一覧表示され、How タグで絞り込める。
- **AC-07 (US-07)**: AirPods 非接続・非対応でも、手動ラベルで How カード生成まで到達できる。
- **AC-08 (NFR)**: センサー取得中もスクロール・タップ操作が滑らかに反応する。
- **AC-09 (US-02)**: AirPods 接続時は頭部モーションが優先記録され、未接続時は本体モーション/手動へフォールバックする。
- **AC-10 (US-08)**: ヘルス権限許可時、心拍トレンドがタイムラインに重ねて表示される。
- **AC-11 (US-09)**: 時間同期歌詞が取得できる曲では、反応地点に対応する歌詞行が表示される。

## 9. Decisions（確定 / 未決）

### 9.1 確定（grill 2026-05-24）

> 設計審問（grill）で確定した決定。

- **[DEC-A] 主シグナルは頭部モーション。** AirPods 頭部モーション（CMHeadphoneMotionManager）と iPhone 本体モーション（Core Motion）を主シグナルとする。リアルタイム・確実に取れる加速度系を中心に据える。
- **[DEC-B] 心拍は補助。** AirPods Pro 3 は心拍数のみ（HRV 不可）で、第三者アプリからのリアルタイム取得に制約があるため、心拍は MVP 必須にしない。取得できればトレンドとして補助的に使う（FR-HR-02/03）。→ DECISION-06/07 に反映。
- **[DEC-C] 推論はルールベース主体 + Core ML 並行。** MVP は閾値ルールで 6 軸スコアを確実に算出する。`ai-recognition/` で TensorFlow 学習を並行し、間に合えば同一インターフェースで Core ML に差し替える。→ DECISION-02 を解決。
- **[DEC-D] MVP は1人分のコア体験を完結。** 「聴く → 頭部モーション → 6 軸スコア → AI 対話 → How カード」を確実に動かす。コミュニティはダミーデータで提示、歌詞・共有は P1。

### 9.2 未決（Deferred）

> SDD では未決事項を仕様段階で明示し、設計段階で解消する。

- **[DECISION-01] 音源と再生位置の取得手段。** ⏳ 保留中（**MusicKit を予定**。要 entitlement・再生位置取得の検証。デモ確実性の代替として AVFoundation + ローカル音源あり）。**MVP の成否を最も左右する決定。**
- **[DECISION-02] 6 軸推論の実行位置。** ✅ **DEC-C で解決**: 端末上、ルールベース主体 + Core ML 並行。
- **[DECISION-03] データ永続化先。** Firestore（iOS SDK）/ CloudKit / Supabase / その他。
- **[DECISION-04] LLM 連携経路。** `backend/` プロキシ経由を前提。既存プロキシ流用可否。
- **[DECISION-05] 共有機能（FR-COMM-04）を MVP に含めるか。** → DEC-D により **P1**（MVP 必須から除外）。
- **[DECISION-06] 心拍のリアルタイム同期方式。** ✅ **DEC-B で方針決定**（補助扱い）。実機での取得粒度は [DECISION-07] で要検証。
- **[DECISION-07] AirPods 心拍の取得 API と対応機種の確定。** ⏳ 要実機検証（AirPods Pro 3 = HR のみ／HRV 不可、第三者アプリのリアルタイム取得粒度を確認）。
- **[DECISION-08] 歌詞ソースと時間同期方式。** 歌詞 API の選定、楽曲との時刻同期手段。

## 10. Glossary

- **How**: 「どう聴いているか」という聴き方の価値観。曲・ジャンル等の「What」と対比。
- **How カード**: 対話で言語化された聴き方を、共有可能な形にまとめたカード（タイトル・説明・How タグ）。
- **How タグ**: groove / chill / neutral を起点とする聴取状態の分類。
- **反応区間**: モーション・心拍から検出された、身体・生理反応が起きていた曲中の時間帯。
- **頭部モーション**: AirPods 内蔵センサーで取得する頭部の加速度・回転速度・姿勢。`CMHeadphoneMotionManager` で取得。
- **心拍変動 (HRV)**: 心拍間隔のゆらぎ。緊張・リラックスなどの生理状態の指標。
- **CMHeadphoneMotionManager**: AirPods 等の頭部モーションを取得する iOS（Core Motion）の API。
- **HealthKit**: iOS のヘルスデータ（心拍等）を扱うフレームワーク。機微情報として明示同意が必要。
- **MusicKit**: Apple Music の楽曲再生・再生位置取得を提供する iOS フレームワーク。
- **Core ML**: iOS 端末上で機械学習モデルを実行するフレームワーク。
