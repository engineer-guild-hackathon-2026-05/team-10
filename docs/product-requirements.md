# プロダクト要求定義書 (Product Requirements Document)

> 対象プラットフォーム: **iOS ネイティブアプリ（Xcode / SwiftUI）**。仕様の source of truth は [`frontend-spec.md`](./frontend-spec.md)（Notion ミラー）。

## プロダクト概要

### 名称
**HowTune** - 何を聴くかではなく、どう聴いているかでつながる音楽コミュニティ

### プロダクトコンセプト
- **How でつながる**: 好きな曲・アーティストではなく「音楽の楽しみ方（How）」でユーザーをマッチングする
- **身体・生理反応の言語化**: AirPods の頭部モーション・心拍と iPhone のモーションで曲中の反応を検出し、AI 対話で言語化する
- **Howカードによる自己表現**: 「グルーヴ派」「余韻に浸る人」などの Howタグ・Howカードで音楽観を共有する

### プロダクトビジョン
音楽の熱狂が本当に伝わるのは「何が好きか」ではなく「どう聴いているか」が共有されたときだ。
HowTune は、AirPods と iPhone のセンサーから曲中の身体・生理反応を検出し、AI との対話を通じて楽しみ方を可視化する。
同じ曲やジャンルではなく、同じ聴き方をしている人との出会いを生み出し、音楽の熱狂を「What」から「How」へ転換する。

### 目的
- 音楽の楽しみ方（How）を言語化できずにいる人が自分の感性を発見できるようにする
- 同じ聴き方をする人と出会える場を提供し、音楽コミュニティの解像度を高める
- AI とのインタラクションを通じて、新しい音楽の楽しみ方を発見・拡張できる体験を作る

## 機能要件

> 詳細な EARS 記法の機能要件は [`frontend-spec.md`](./frontend-spec.md) を正とする。本書は P0/P1/P2 の優先度づけを担う。

### コア機能（MVP / P0）

#### 1. オンボーディング・権限取得
AirPods 接続、モーション（Core Motion）・ヘルス（HealthKit）権限の取得。拒否時は手動ラベルへフォールバック。
**受け入れ条件**:
- [ ] ユーザー操作起点でモーション/ヘルス許可ダイアログを出せる
- [ ] 権限拒否・AirPods 未接続でも手動ラベルモードに進める
**優先度**: P0

#### 2. 楽曲再生 × センサー取得（3系統）

**ユーザーストーリー**: 音楽好きとして、自分の反応を記録するために、曲を聴きながらセンサーが自動取得されてほしい

**受け入れ条件**:
- [ ] 曲を再生し、再生位置（曲中時刻）を継続取得できる（MusicKit 想定）
- [ ] AirPods の頭部モーションを `CMHeadphoneMotionManager` で取得できる
- [ ] iPhone 本体モーションを Core Motion で取得できる
- [ ] 心拍を HealthKit で取得し曲中時刻に対応づけられる
- [ ] AirPods 切断時は本体モーションへフォールバックする

**優先度**: P0

#### 3. 反応区間の検出（3状態スコア）
**受け入れ条件**:
- [ ] 5秒窓で特徴量（モーション + 心拍）を抽出し3状態スコアを推定
- [ ] groove / chill / neutral を取得
- [ ] 反応区間をタイムラインに可視化
**優先度**: P0（推論は TF 学習 → Core ML 変換、端末推論を想定。DECISION-02）

#### 4. AI 対話による言語化
**受け入れ条件**:
- [ ] 反応地点に基づく確認形（断定でない）の問いかけを生成
- [ ] 選択肢／自由入力で回答、複数ターンの深掘り
- [ ] LLM 障害時は手動入力へフォールバック
**優先度**: P0

#### 5. Howカード生成・編集・保存
**受け入れ条件**:
- [ ] 対話結果から Howカード（タイトル・説明・Howタグ）を生成
- [ ] プレビュー・編集後、確定操作をするまで保存しない（自動確定不可）
**優先度**: P0

#### 6. 同じHowの人・曲・リスナーの表示
**受け入れ条件**:
- [ ] Howタグで絞り込んだユーザー・曲・リスナーを表示
- [ ] 自分のHowを表示
**優先度**: P0

#### 7. 歌詞表示（反応地点に対応）
**受け入れ条件**:
- [ ] 時間同期歌詞が取得できる曲で、反応地点の歌詞行を表示
- [ ] 取得できない場合は時刻のみ表示
**優先度**: P1（歌詞 API 連携。DECISION-08）

## 非機能要件

### パフォーマンス
- センサー取得・特徴量抽出はメインスレッドを阻害しない
- 反応検出から問いかけ提示までの遅延を体感的に短く保つ
- 連続センサー取得＋再生時の電力・発熱を抑制する

### ユーザビリティ
- 初回ユーザーがオンボーディング〜Howカード生成まで完了できる（目標5分以内）
- VoiceOver・Dynamic Type 対応

### 信頼性
- 通信断でセンサーデータを失わない（ローカルバッファ→再送）
- LLM 障害時はフォールバックでセッション継続

### セキュリティ・プライバシー
- LLM/推論 API キーをクライアントに置かず backend 経由
- 認証トークンは iOS Keychain に保持
- 心拍は HealthKit の機微情報として最小権限・明示同意・端末内処理優先・削除手段を提供

## スコープ外（意図的に除外）
- Web 版（iOS ネイティブに一本化）
- Android 対応
- DM・フォロー・完全なタイムライン型フィード
- 本格的な音源解析・高精度 BPM 推定
- 教師データ収集アプリ（別仕様 `002-` に分離）
