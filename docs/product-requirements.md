# プロダクト要求定義書 (Product Requirements Document)

> 対象プラットフォーム: **iOS ネイティブアプリ（Xcode / SwiftUI）**。仕様の source of truth は [`frontend-spec.md`](./frontend-spec.md)（Notion ミラー）。

## プロダクト概要

### 名称
**HowTune** - 何を聴くかではなく、どう聴いているかでつながる音楽コミュニティ

### プロダクトコンセプト
- **How でつながる**: 好きな曲・アーティストではなく「音楽の楽しみ方（How）」でユーザーをマッチングする
- **身体・生理反応の言語化**: AirPods の頭部モーション・心拍と iPhone のモーションで曲中の反応を検出し、AI 対話で言語化する
- **Howカードによる自己表現**: 「グルーヴ派」「余韻に浸る人」などの Howタグ・Howカードで音楽観を共有する

### プロダクトビジョン
音楽の熱狂が本当に伝わるのは「何が好きか」ではなく「どう聴いているか」が共有されたときだ。
HowTune は「動いて・問いかけて・つながる」という3ステップで体験を設計する。
センサーが身体のモメンタムを捉え、AIが波形を読んで問いかけ、言語は発見の後についてくる。
同じ波形を持つ見知らぬ人との出会いが、音楽の熱狂を「What」から「How」へ転換する。

### コア体験の設計原則
- **聴く（Listen）**: 曲を再生する。歌詞が時刻同期で流れる
- **刺さる（React）**: 「この歌詞だ」と思った行をタップする。その瞬間の Groove レベルが記録される
- **掘り下げる（Discover）**: AI が歌詞と反応を起点に問いかける。言語化はその後についてくる
- **つながる（Connect）**: 同じ歌詞・同じ How に反応した人と出会う

### AI の役割定義：鏡であること

身体は、言語より先に知っている。

groove が走った瞬間、hype が弾けた瞬間——それはまだ言葉になる前の何かだ。HowTune のセンサーはその「まだ名前のない反応」を、身体が動いたという純粋な事実として静かに記録する。

AI の役割は、そこに意味を書き込むことではない。ユーザーが自分の内側にすでに持っている何かを、**映し出す鏡**であること。

問いかけは断定ではなく、光の角度を変えることだ。「1:18、身体が動いていた。その瞬間、何がありましたか？」——AI は事実だけを差し出し、扉を開く。扉の向こうに何があるかを決めるのは、ユーザー自身だ。

これは Calabi-Yau 多様体の断面に似ている。内的体験は高次元にあり、直接見ることができない。センサーはその断面を一枚切り出し、AI はそれをユーザーの前に静かに置く。どの断面に意味を見るかは、ユーザーが決める。

> **センサーは事実を捉える。AI は断面を差し出す。意味はユーザーが発見する。**

この原則が崩れ、AI がユーザーの感情を断定した瞬間、体験は壊れる。鏡が「あなたはこう感じている」と語り始めたなら、それはもう鏡ではない。

### 目的
- 自分の身体反応（モメンタム）を初めて可視化する驚きの体験を提供する
- AIの問いかけを通じて、言語化できなかった感性を発見できるようにする
- 同じ波形・聴き方をする人と出会える場を提供し、音楽コミュニティの解像度を高める

## 機能要件

> 詳細な EARS 記法の機能要件は [`frontend-spec.md`](./frontend-spec.md) を正とする。本書は P0/P1/P2 の優先度づけを担う。

### コア機能（MVP / P0）

#### 1. 楽曲再生 × 時刻同期歌詞表示

**ユーザーストーリー**: 音楽好きとして、曲を聴きながら歌詞がリアルタイムで流れ、気になった行をタップしたい

**受け入れ条件**:
- [ ] 曲を再生し、再生位置（曲中時刻）を継続取得できる（MusicKit）
- [ ] Musixmatch API で歌詞を取得し、時刻同期で表示できる
- [ ] 歌詞が取得できない曲は時刻のみ表示（フォールバック）
- [ ] 現在の再生位置に対応する歌詞行をハイライトする

**優先度**: P0（ADR-0004）

#### 2. 歌詞行タップ → AI 対話 → HowCard 生成

**ユーザーストーリー**: 気になった歌詞行をタップして、AIと対話しながら「どう刺さったか」をHowCardにしたい

**受け入れ条件**:
- [ ] 歌詞行タップで HowChatView が開く
- [ ] 歌詞テキスト・再生時刻・Groove レベルが AI の問いかけに組み込まれる
- [ ] 選択肢／自由入力で回答、複数ターンの深掘り
- [ ] 対話結果から HowCard（タイトル・説明・Howタグ）を生成
- [ ] プレビュー・編集後、確定操作をするまで保存しない

**優先度**: P0

#### 3. Groove レベル表示
**受け入れ条件**:
- [ ] 再生中に音量ベースの Groove レベル（0〜100%）をリアルタイム表示する
- [ ] Groove レベルから HowTag（groove / hype / chill / immersion / afterglow）を推定し HowCard に反映する
- [ ] AirPods 接続時は頭部モーションで補完できる（補助、ADR-0005）
**優先度**: P0（ADR-0005）

#### 4. AI 対話による言語化
**受け入れ条件**:
- [ ] 反応地点に基づく確認形（断定でない）の問いかけを生成
- [ ] 選択肢／自由入力で回答、複数ターンの深掘り
- [ ] LLM 障害時は手動入力へフォールバック
**優先度**: P0

#### 5. Howカード生成・編集・保存
**受け入れ条件**:
- [ ] 対話結果から Howカード（タイトル・説明・Howタグ）を生成
- [ ] プレビュー・編集後、確定操作をするまで保存しない（自動確定不可）
**優先度**: P0

#### 6. 同じHowの人・曲・リスナーの表示
**受け入れ条件**:
- [ ] Howタグで絞り込んだユーザー・曲・リスナーを表示
- [ ] 自分のHowを表示
**優先度**: P0

#### 7. 歌詞表示（反応地点に対応）
**受け入れ条件**:
- [ ] 時間同期歌詞が取得できる曲で、反応地点の歌詞行を表示
- [ ] 取得できない場合は時刻のみ表示
**優先度**: P1（歌詞 API 連携。DECISION-08）

- **ライブ会場での反応共有**: 会場単位のリアルタイム集合反応ヒートマップ

## 非機能要件

### パフォーマンス
- センサー取得・特徴量抽出はメインスレッドを阻害しない
- 反応検出から問いかけ提示までの遅延を体感的に短く保つ
- 連続センサー取得＋再生時の電力・発熱を抑制する

### ユーザビリティ
- 初回ユーザーがオンボーディング〜Howカード生成まで完了できる（目標5分以内）
- VoiceOver・Dynamic Type 対応

### 信頼性
- 通信断でセンサーデータを失わない（ローカルバッファ→再送）
- LLM 障害時はフォールバックでセッション継続

### セキュリティ・プライバシー
- LLM/推論 API キーをクライアントに置かず backend 経由
- 認証トークンは iOS Keychain に保持
- 心拍は HealthKit の機微情報として最小権限・明示同意・端末内処理優先・削除手段を提供

## 収益モデル

### 設計原則: プラスサム

アーティスト・リスナー・プラットフォームが三者ともに価値を得る設計。チップを送った側も「発見者」として可視化することでゼロサムにならない。

### 3本柱

#### 1. アーティスト向けインサイト（B2B）

既存の再生数・ストリーム数ではなく、**身体反応ヒートマップ**という新しいデータをアーティスト・レーベルに提供する。

- 「この曲の1分18秒にgroove反応が集中する」などの反応地点分析
- HowタグのファンDB（どんな聴き方をするファンが多いか）
- 提供形態: アーティストダッシュボード（月額サブスク）

> Spotify Analytics にないデータで差別化できる。

#### 2. チップ循環（P2P × アーティスト支援）

| フロー | 内容 | マージン |
|---|---|---|
| リスナー → アーティスト | 楽曲・反応地点への感謝チップ | 10% |
| リスナー → リスナー | 同じHowを持つ人への共鳴チップ | 10% |

- チップを**送った側**も「最初に気づいた人」として可視化（発見者インセンティブ）
- アーティストに直接還元される構造でファンの心理的ハードルを下げる

#### 3. セレンディピティマッチング（Premium）

「同じ曲の同じ瞬間に同じように反応した見知らぬ人」との出会いをプレミアム機能として解禁。

- テーマ（How）で繋がるため、既存の趣味マッチングより解像度が高い
- 偶然性（セレンディピティ）が体験価値になる

## 中長期ロードマップ

### フェーズ別計画

| フェーズ | 時期 | 主要機能 | 収益 |
|---|---|---|---|
| **MVP** | 今（ハッカソン） | How記録・AI対話・Howカード・コミュニティ | 無料 |
| **Phase 1** | 〜6ヶ月 | アーティストダッシュボード | B2Bサブスク |
| **Phase 2** | 〜1年 | チップ機能（P2P・アーティスト） | マージン10% |
| **Phase 3** | 〜2年 | セレンディピティマッチング・曲推薦 | プレミアム |
| **Phase 4** | 2年〜 | ライブ会場リアルタイム反応・レーベル提携 | エンタープライズ |

### アーティストを中心に置く理由

- アーティストへの還元がリスナーの利用動機を高める（応援消費）
- アーティストの公式参加がコンテンツ信頼性を高める
- 身体反応データはアーティストの創作にもフィードバックできる

### エコシステムの構造

```
アーティスト ←── チップ・インサイト ──── HowTune（プラットフォーム）
     ↑                                          ↑
  応援動機                                  マージン
     │                                          │
リスナー A ─── Howでつながる ─── リスナー B ───┘
（発見者）                        （共鳴者）
```
