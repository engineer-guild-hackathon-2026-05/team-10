# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**HowTune** - 何を聴くかではなく、どう聴いているかでつながる音楽コミュニティ

### プロダクトコンセプト
- **HowでつながるSNS**: 好きな曲・アーティストではなく「音楽の楽しみ方（How）」でユーザーをマッチングする
- **身体反応の言語化**: スマホの加速度センサーで曲中の身体反応を自動検出し、AIとの対話で言語化を支援する
- **Howカードによる自己表現**: 「グルーヴ派」「余韻に浸る人」などのHowタグ・Howカードで自分の音楽観を共有できる

### プロダクトビジョン
音楽の熱狂が本当に伝わるのは「何が好きか」ではなく「どう聴いているか」が共有されたときだ。
HowTuneは、スマホの動きから曲中の身体反応を検出し、AIとの対話を通じて楽しみ方を可視化する。
同じ曲やジャンルではなく、同じ聴き方をしている人との出会いを生み出すことで、
音楽の熱狂を「What」から「How」へと転換し、より深いコミュニティを形成する。

### 目的
- 音楽の楽しみ方（How）を言語化できずにいる人が自分の感性を発見できるようにする
- 同じ聴き方をする人と出会える場を提供し、音楽コミュニティの解像度を高める
- AIとのインタラクションを通じて、新しい音楽の楽しみ方を発見・拡張できる体験を作る

## ターゲットユーザー

### プライマリーペルソナ: 田中音（22歳、大学生・音楽好き）
- SpotifyやApple Musicで毎日1〜2時間音楽を聴く
- 好きな曲はあるが「なぜ好きか」をうまく説明できない
- SNSで音楽についてもっと語りたいが、「好きな曲の名前を共有する」以上のことができていない
- 同じアーティストのファンとは会えるが、「自分と同じ楽しみ方をしている人」とは出会えていない
- **期待する解決策**: 自分の音楽の楽しみ方を言語化してもらい、同じ聴き方の人と出会いたい

### セカンダリーペルソナ: 鈴木聴（28歳、社会人・音楽マニア）
- 年間500枚以上のアルバムを聴く熱心なリスナー
- 「ベースラインの動き方が好き」「Aメロの緊張感が好き」など、楽しみ方は言語化できている
- しかし同じ観点で語れる相手がいない
- **期待する解決策**: 音楽の「聴き方」を共有できるコミュニティに参加したい

## 機能要件

### コア機能（MVP）

#### 1. 音楽再生 × センサー取得

**ユーザーストーリー**:
音楽好きとして、自分の身体反応を記録するために、スマホで曲を再生しながら加速度データを自動取得したい

**受け入れ条件**:
- [ ] ブラウザ上で曲を再生できる（アップロードまたはURL指定）
- [ ] DeviceMotionEvent API で x/y/z 軸の加速度を100ms間隔で取得できる
- [ ] 曲の再生タイムスタンプとセンサー値を紐付けて記録できる
- [ ] iOS/Android のブラウザで動作確認済み（センサー許可フローを含む）

**優先度**: P0（必須）

---

#### 2. 身体反応の区間検出（MotionReactionClassifier）

**ユーザーストーリー**:
音楽好きとして、自分が「ノった」「上がった」「刺さった」瞬間を振り返るために、センサーデータから自動的に反応区間を検出してほしい

**受け入れ条件**:
- [ ] TensorFlow.js でセンサー特徴量から6軸スコアを推定できる（Groove/Hype/Chill/Immersion/Hit/Afterglow）
- [ ] 特徴量として `meanMagnitude`, `stdMagnitude`, `maxDelta`, `energy`, `peakCount`, `rhythmRegularity` を使用する
- [ ] 各1〜3秒の時間窓でリアルタイムに推定できる
- [ ] 推定スコアがタイムライン上に可視化される

**優先度**: P0（必須）

---

#### 3. AI 対話による言語化

**ユーザーストーリー**:
音楽好きとして、自分の漠然とした感覚を言葉にするために、AIが検出した反応地点をもとに問いかけてくれる対話を体験したい

**受け入れ条件**:
- [ ] 検出した反応区間のタイムスタンプと推定状態をもとに、AIが具体的な質問を生成できる
- [ ] 例：「1:18あたりで動きが大きくなっていました。ベースの入り方が好きでしたか？それとも展開で上がりましたか？」
- [ ] ユーザーが自由入力または選択肢で回答できる
- [ ] 3ターン以上の対話で言語化の精度が向上する設計
- [ ] 断言型（「あなたはベースが好きです」）ではなく、問いかけ型（「ベースが好きでしたか？」）の口調を維持する

**優先度**: P0（必須）

---

#### 4. Howカード生成

**ユーザーストーリー**:
音楽好きとして、自分の音楽の楽しみ方を他の人に伝えるために、AI対話の結果からHowカードを生成・共有したい

**受け入れ条件**:
- [ ] AI対話の内容をもとに、Howタグ（例：「ベースの入りに反応する人」「余韻に浸るタイプ」）を生成できる
- [ ] カードには：Howタグ名、説明文（2〜3文）、対応する曲名・タイムスタンプが含まれる
- [ ] カードをSNS共有用の画像またはURLとして出力できる
- [ ] カード生成が10秒以内に完了する

**優先度**: P0（必須）

---

#### 5. 同じHowの人との発見

**ユーザーストーリー**:
音楽好きとして、自分と同じ楽しみ方をしている人を見つけるために、Howタグで他のユーザーを検索・閲覧したい

**受け入れ条件**:
- [ ] Howタグでフィルタリングしたユーザー一覧を表示できる
- [ ] 各ユーザーのHowカード（最新1〜3枚）を一覧で見られる
- [ ] 同一曲を異なるHowで聴いているユーザーの比較が可能
- [ ] 一覧の読み込みが2秒以内に完了する

**優先度**: P0（必須）

---

### 強化機能（Post-MVP / P1）

#### 6. 教師データ収集アプリ

音楽を聴きながらリアルタイムでラベルボタン（ノってる / 上がった / チルい 等）を押し、加速度データと紐付けて保存する。MotionReactionClassifier の精度向上に使用。

**優先度**: P1（重要）

---

#### 7. Howタグによるコミュニティ

HowタグをベースにしたグループUI。グルーヴ派・余韻派などのコミュニティで投稿・閲覧できる。

**優先度**: P1（重要）

---

#### 8. Howによる曲推薦

自分と同じHowを持つ他ユーザーが高評価している曲のレコメンド。

**優先度**: P2（できれば）

## 非機能要件

### パフォーマンス
- センサーデータの取得・記録: 100ms間隔でドロップなし（60秒セッション中）
- TensorFlow.js 推論: 1窓あたり50ms以内
- Howカード生成（LLM含む）: 10秒以内
- 同じHowのユーザー一覧表示: 2秒以内

### ユーザビリティ
- 初回ユーザーがチュートリアルなしで曲再生〜Howカード生成まで完了できる（目標：5分以内）
- センサー許可ダイアログの説明文が明確で、ユーザーが迷わず許可できる
- モバイルファースト設計（タップ操作のみで全機能が使える）

### 信頼性
- センサーデータは60秒ごとにバックエンドに自動保存する（データロスト防止）
- LLM API障害時はフォールバックメッセージを表示し、セッションを継続できる

### セキュリティ
- センサーデータはユーザー認証後のみ保存・閲覧できる
- API キーはサーバーサイドのみで使用し、クライアントに露出させない
- DeviceMotionEvent の使用目的をプライバシーポリシーに明記する

### スケーラビリティ
- Cloud Run のオートスケールで同時50セッションまで対応（ハッカソン期間中の想定）
- Firestore の読み取りは1秒あたり最大100リクエストを想定した設計

---

## スコープ外（意図的に除外）

- DM・フォロー機能（SNS化しない）
- 完全なタイムライン型フィード
- Spotify / Apple Music の公式 API 連携
- 歌詞 API 連携
- 本格的な音源解析（BPM推定・コード解析）
- マルチデバイス同期（ハッカソン期間は単一デバイス想定）
- モデルの本番サービング（TensorFlow.js をブラウザ/Node.js で完結）
