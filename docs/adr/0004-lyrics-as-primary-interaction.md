# ADR-0004: 歌詞行タップを HowCard 生成のコア UX に採用する

- **ステータス**: 採用済み
- **決定日**: 2026-05-25
- **決定者**: Team 10

## 背景

初期設計では「センサーが自動検出した反応区間」を起点に AI 対話を始める想定だった。
しかし実装を進める中で、以下の課題が浮上した。

- センサー検出の精度は MVP 段階では低く、「ここで反応した」という根拠が弱い
- ユーザーに「センサーに言語化を任せる」体験を求めるには、センサーへの信頼が必要
- 歌詞という「すでに意味のある単位」の方が、ユーザーが自分の反応を振り返りやすい

一方、PR #53 で Musixmatch API による時刻同期歌詞表示が実装され、
「歌詞行 × 再生位置」の組み合わせが自然なインタラクション起点になることが見えた。

## 検討した選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| **歌詞行タップ → AI 深掘り（採用）** | 直感的。歌詞という共通言語で反応を特定できる | 歌詞取得できない曲はフォールバックが必要 |
| センサー反応区間 → AI 深掘り（旧設計） | 身体反応起点で差別化できる | MVP 段階の精度が不十分 |
| 自由時刻指定 → AI 深掘り | 汎用的 | 「どこで反応したか」を覚えていないと機能しない |

## 決定

**HomeView の歌詞リスト（`lyricsSection`）を HowCard 生成の主要エントリーポイントとする。**

各歌詞行（`lyricScrollRow`）には `howActionStrip` を配置し、以下を提供する：

- **「X How」**: この歌詞行に紐づいた HowCard の数（コミュニティとの接点）
- **「コメント」**: この歌詞行への直接コメント
- **「AIと深掘り」**: 歌詞行をコンテキストに HowChatView を開く

歌詞行タップで `openHowCard(for: TimedLyricLine)` が呼ばれ、
行の時刻・テキスト・現在の Groove レベルから `ReactionEvent` を生成して HowChatView に渡す。

```
歌詞行タップ
  → openHowCard(for: line)
  → reactionEvent(for: line)  // 時刻・強度・HowTag を生成
  → selectedHowChatEvent = event
  → HowChatView(event:) をシートで表示
  → AI 対話 → HowCard 生成・保存
```

## 結果

- センサー精度に依存せずに HowCard 生成フローが成立する
- 「この歌詞で反応した」という文脈が AI の問いかけに組み込まれ、対話が具体的になる
- 歌詞行はコミュニティとの共通言語になる（同じ歌詞行に What How が集まる）
- 歌詞が取得できない曲は時刻表示にフォールバックし、体験が完全に壊れない（FR-LYRIC-02）

## 影響する仕様

- `frontend-spec.md`: FR-LYRIC-01/02 を P0 に格上げ（DECISION-08 解決済み）
- `product-requirements.md`: 歌詞表示を「コア機能（P0）」に変更
