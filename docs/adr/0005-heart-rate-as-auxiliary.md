# ADR-0005: 心拍は補助シグナルとする

- **ステータス**: 採用済み
- **決定日**: 2026-05-25
- **決定者**: Team 10（grill による設計審問で確定）

## 背景

身体反応の検出に、AirPods の頭部モーション・心拍、iPhone 本体モーションを使う。
このうち心拍（HealthKit）を MVP でどう位置づけるかを検討した。

AirPods Pro 3 は心拍数のみ取得可能（HRV 非対応）で、**第三者 iOS アプリからのリアルタイム心拍取得には制約がある**（実機検証が未完）。純正 Fitness アプリはワークアウト中に連続取得できるが、第三者アプリへの提供粒度は枯れていない。

## 検討した選択肢

| 選択肢 | メリット | デメリット |
|---|---|---|
| **心拍は補助** | 主シグナル（頭部モーション）が確実に動く。心拍が取れなくてもデモが成立 | 心拍そのものの訴求は弱まる |
| 心拍を主シグナル | 生理反応で説得力が出る | リアルタイム取得が不確実。MVP が心拍依存で崩れるリスク |
| 心拍を使わない | 実装が単純 | 「生理反応」という訴求を失う |

## 決定

**心拍は補助シグナル**とし、**主シグナルは頭部モーション（CMHeadphoneMotionManager）＋ 本体モーション（Core Motion）**とする。

- 心拍は取得できればトレンド（上昇 / 下降 / 安定）として補助的に使う
- 心拍のリアルタイム取得が不確実な場合でも、モーションのみで体験が成立する（FR-HR-02 / FR-HR-03）

## 結果

- MVP はリアルタイム・確実に取れる加速度系（頭部・本体モーション）を中心に、確実に動く
- 心拍は取れた場合に「生理反応の裏付け」として高揚・没入の判定を補強する
- 心拍のリアルタイム取得粒度は実機検証が必要（要検証項目として残す）
- 関連: ADR-0004（画面を見ない音楽体験）、ADR-0003（ルールベース → フライホイール）
